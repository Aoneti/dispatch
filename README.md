# Dispatch — расширение Chrome «RSS в X»

Простое локальное расширение для Google Chrome (Manifest V3) на русском языке. Собирает новости из добавленных вами RSS и Atom-лент, позволяет удобно читать статьи, отмечать прочитанные, сохранять на потом и **только по вашему нажатию** генерирует отдельный пост для X через выбранного вами AI-провайдера — **Google Gemini** (`gemini-3.1-flash-lite`) или **Groq** (`openai/gpt-oss-120b` / `openai/gpt-oss-20b`).

Расширение ничего не публикует в X автоматически, не запрашивает доступ к аккаунту X и не использует собственный сервер, регистрацию, аналитику или телеметрию.

---

## Что умеет расширение

- **Новости** — единая лента статей из всех добавленных RSS/Atom-источников:
  - заголовок, название источника, дата публикации и краткое описание;
  - поиск по заголовку, тексту, автору и источнику;
  - фильтры: все, непрочитанные, прочитанные, сохранённые;
  - сортировка по дате (сначала новые / сначала старые);
  - управление статусами прочтения и сохранения в просмотре статьи и с клавиатуры (**R** — прочитать/вернуть в непрочитанные, **S** — сохранить/убрать из сохранённых);
  - массовые действия: прочитать всё в текущем представлении, прочитать источник, с возможностью отмены (`Отменить`);
  - счётчики непрочитанных в общем списке, для каждого источника и в значке расширения;
  - кнопка **«Обновить»** для ручного обновления лент (плюс фоновое расписание: 15 минут / 30 минут / 1 час / 3 часа, меняется в настройках);
  - чтение статьи, переход к оригиналу и кнопка **«Извлечь полный текст»**, если в RSS пришёл только короткий анонс;
  - две независимые кнопки генерации: **«Сгенерировать короткий пост»** и **«Сгенерировать расширенный пост»**.
- **Источники** — управление лентами:
  - добавление RSS 2.0 и Atom по прямой ссылке с предварительной проверкой;
  - настройка названия источника;
  - включение/отключение, обновление отдельной ленты или всех сразу, редактирование и удаление;
  - отображение количества статей, непрочитанных, числа элементов в ленте и времени последней синхронизации;
  - загрузка более старых публикаций, если лента поддерживает пагинацию (RFC 5005);
  - дедупликация статей по GUID, каноническому URL и контрольной сумме текста — повторные обновления не создают дубликаты;
  - поддержка условных HTTP-запросов (`ETag` / `Last-Modified`).
- **Черновики** — независимые посты (каждый черновик соответствует одному формату — короткому или расширенному):
  - текстовый редактор с автосохранением и живым счётчиком символов;
  - отображение провайдера и модели, которыми был создан пост (`Google Gemini · gemini-3.1-flash-lite` или `Groq · openai/gpt-oss-120b`);
  - кнопки **«Сохранить»**, **«Копировать»**, **«Копировать со ссылкой»** (ссылка на оригинал хранится отдельно и добавляется только по вашему выбору), **«Исходный текст»** (возврат первоначального варианта ИИ) и **«Удалить»**;
  - при повторной генерации уже существующего формата выводится предупреждение о замене (с отдельным акцентом, если черновик редактировался вручную).
- **Настройки** — всё в одном месте:
  - переключатель **«Активный AI-провайдер»**: **Google Gemini** или **Groq**;
  - независимый блок **Google Gemini** (`gemini-3.1-flash-lite`): отдельный API-ключ, показать/скрыть, сохранить, заменить, удалить, **«Проверить подключение»**, согласие на передачу текста и статистика;
  - независимый блок **Groq**: выбор модели (`GPT-OSS 120B` или `GPT-OSS 20B`), отдельный API-ключ, показать/скрыть, сохранить, заменить, удалить, **«Проверить подключение»** (строго для выбранной модели), отдельное согласие на передачу текста и статистика;
  - тема оформления (светлая, тёмная, системная), автоматическое прочтение и интервал обновления RSS;
  - очистка старых прочитанных статей (по явному выбору, с сохранением сохранённых и непрочитанных);
  - экспорт и импорт данных в JSON (оба API-ключа в экспорт не попадают), очистка локальных данных.

## Два AI-провайдера: Google Gemini и Groq

Пользователь самостоятельно выбирает в настройках, какой провайдер использовать для генерации постов. Оба провайдера работают по единому редакторскому промпту Dispatch и возвращают одинаковую проверенную структуру ответа.

### 1. Google Gemini (активен по умолчанию)
- Официальный REST endpoint:
  `POST https://generativelanguage.googleapis.com/v1beta/models/gemini-3.1-flash-lite:generateContent`
- Модель: фиксированная **`gemini-3.1-flash-lite`**.
- Аутентификация: заголовок `x-goog-api-key`.
- Получение ключа: **https://aistudio.google.com/apikey**.

### 2. Groq API
- Официальный OpenAI-совместимый REST endpoint:
  `POST https://api.groq.com/openai/v1/chat/completions`
- Аутентификация: заголовок `Authorization: Bearer GROQ_API_KEY`.
- Структурированный вывод: **Groq Structured Outputs** (`response_format.type = "json_schema"`, `strict: true`) и параметр `max_completion_tokens`.
- Доступные для осознанного выбора модели:
  - **`openai/gpt-oss-120b` (GPT-OSS 120B)** — выбрана по умолчанию, основная модель с приоритетом качества;
  - **`openai/gpt-oss-20b` (GPT-OSS 20B)** — более быстрая альтернатива.
- Получение ключа: **https://console.groq.com/keys** (документация: **https://console.groq.com/docs**).

### Важные правила работы провайдеров
- **Отдельные API-ключи и согласия.** Ключ Google Gemini и ключ Groq хранятся раздельно (`dispatch.gemini.key.v1` / `dispatchGeminiKeyV1` и `dispatch.groq.key.v1` / `dispatchGroqKeyV1`). Согласие на отправку статьи в Google Gemini не считается согласием для Groq — каждый провайдер подтверждается отдельно.
- **Только ручной запуск.** Выбор активного провайдера, смена модели Groq, сохранение ключей, открытие статьи, переключение новостей и обновление RSS **никогда** не вызывают AI-запросы. Запрос отправляется только при нажатии кнопки короткого или расширенного поста либо кнопки «Проверить подключение».
- **Никакого автоматического переключения.** При ошибке выбранного провайдера или модели расширение не переключается автоматически на другой провайдер или другую модель.
- **Контролируемая обработка ошибок:**
  - **5xx / сетевой сбой / таймаут** — экспоненциальный backoff с джиттером (не более 2 повторов);
  - **429 (частота запросов в минуту)** — учитываются `RetryInfo` / `Retry-After` и заголовки `x-ratelimit-*`, без бесконечных циклов;
  - **429 (дневная квота исчерпана)** — повторные попытки не выполняются;
  - **400 / 401 / 403 / 404 / отказ модели / блокировка безопасности** — без автоповторов, с понятным сообщением на русском языке.
- Лимиты, квоты и условия обработки данных определяет выбранный вами провайдер (Google или Groq).

## Приватность и безопасность

- **Первый запуск — полностью пустой.** В расширении нет предустановленных RSS-источников, тестовых новостей и демонстрационных черновиков.
- Источники, статьи и черновики хранятся только локально в вашем браузере (IndexedDB + кэш `localStorage`).
- Оба API-ключа хранятся только локально (в профиле браузера и `chrome.storage.local`), не синхронизируются через Chrome Sync, не передаются другому провайдеру и **никогда** не попадают в экспорт JSON, IndexedDB рабочего пространства, логи или метаданные статей.
- **Прямые запросы без сторонних CORS-прокси.** В `manifest.json` постоянные `host_permissions` указаны только для `https://generativelanguage.googleapis.com/*` и `https://api.groq.com/*`, а доступ к сайтам RSS-источников и статей запрашивается точечно через `optional_host_permissions`.
- Текст выбранной статьи передаётся только выбранному вами активному AI-провайдеру и только в момент нажатия кнопки генерации.
- Все HTML-фрагменты из RSS, веб-страниц и импорта очищаются whitelist-санитайзером при сохранении и непосредственно перед рендерингом.
- При обновлении со старых версий (схема `v1` → `v4`) выполняется безопасная миграция: сохраняются все источники, статьи, пользовательские черновики (прежние черновики получают `provider: "gemini"`), настройки и существующий ключ Gemini (`activeProvider` остаётся `"gemini"`).

## Команды разработки и сборки

Требуется **Node.js 20+**.

```bash
npm install                   # установка зависимостей
npm run dev                   # локальный запуск для разработки
npm run build                 # стандартная production-сборка в папку dist
npm run build:extension       # сборка Chrome Extension (Manifest V3) в папку dist
npm run package:extension     # проверка dist и упаковка в dispatch-extension.zip
```

Итог сборки:
- папка **`dist/`** — готовое распакованное расширение (`manifest.json`, `index.html`, `background.js`, `assets/`, `icons/`);
- файл **`dispatch-extension.zip`** — готовый ZIP-архив расширения (создаётся кроссплатформенно через `jszip`, без необходимости системной утилиты `zip`).

Подробная пошаговая инструкция для пользователя Windows находится в файле **[SETUP.md](SETUP.md)**.

## Известные ограничения

- **Фоновое обновление при закрытой панели:** service worker Manifest V3 отмечает наступление расписания, а фактическая загрузка и разбор XML выполняются при открытой боковой панели или сразу при её следующем открытии.
- **Доступ к сайтам:** если сайт защищён от ботов, закрыт платной подпиской (paywall) или пользователь отклонил запрос разрешения Chrome для домена, полный текст извлечь не удастся — расширение сохранит фрагмент из RSS и не будет придумывать факты.
- **Пагинация зависит от издателя:** не все RSS-ленты поддерживают RFC 5005. Если ссылка на архив отсутствует, расширение честно сообщает, что более старые публикации через эту ленту недоступны.
- **Локальное хранение API-ключей:** защита в профиле браузера не равна серверному хранилищу секретов. При доступе посторонних к профилю браузера отзовите и перевыпустите ключи в Google AI Studio и Groq Console.
